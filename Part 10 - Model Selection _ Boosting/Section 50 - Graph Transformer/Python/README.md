# Section 50 - Graph Transformer: catching fraud in a payments network

This section teaches a **graph transformer** (a neural network that learns from *who is connected to whom*) on a realistic fraud-detection problem: finding scam mules, fraud rings, money launderers and taken-over accounts in a mobile-payments network.

Open **[graph_transformer.ipynb](graph_transformer.ipynb)**. Like every notebook in this repo, it explains each step in plain English, and it is saved with all its charts and results, so you can read it without running anything.

## The data

The network is **synthetic**: it is modelled on a mobile-payments company (customers, merchants and cash-in / cash-out agents), but every account and payment is generated by [generate_payments_graph.py](generate_payments_graph.py). No real customer data is used. A fixed random seed means the same command always produces the same files.

| File | Rows | What one row is |
|---|---|---|
| `accounts.csv.gz` (2.8 MB) | 200,000 | an account (a **node** of the graph) |
| `transactions.csv.gz` (33 MB) | 1,954,633 | a payment between two accounts (an **edge** of the graph), over 90 days |

**accounts.csv.gz**

| Column | Meaning |
|---|---|
| `account_id` | unique number for the account |
| `account_type` | `customer`, `merchant` or `agent` (a shop where people pay cash in or take cash out) |
| `account_age_days` | how long ago the account was opened |
| `kyc_level` | how thoroughly the owner's identity was checked (1 = basic, 3 = full) |
| `region` | where the account is registered |
| `device_count`, `device_id` | how many phones use the account, and the main phone's ID (shared phones are a fraud-ring clue) |
| `avg_daily_balance` | typical money held in the account |
| `is_business` | 1 for business accounts |
| `signup_channel` | how the account was opened: `app`, `USSD`, `web` or `agent` |
| `role` | the true role: `normal`, `fraud_ring`, `mule`, `mule_collector`, `launderer` or `account_takeover` |
| `is_fraud` | 1 for any fraud role (3,054 accounts, 1.5%) — **this is what the model predicts** |

**transactions.csv.gz**

| Column | Meaning |
|---|---|
| `tx_id`, `timestamp`, `hour` | payment number, date and time, and hour of day |
| `sender_id`, `receiver_id` | who paid whom (account IDs) |
| `amount` | how much was paid |
| `channel` | `P2P`, `merchant_payment`, `cash_in`, `cash_out`, `bill_pay` or `international` |
| `is_suspicious` | 1 if the payment is part of a planted fraud pattern (1.1%) |

**Planted fraud patterns.** Each fraud account also does ordinary everyday payments, so its own numbers look fairly normal. The giveaway is mostly *who it pays and who pays it*. That is exactly what a graph model can see and a normal table model cannot.

1. **Fraud rings**: small groups of mostly new accounts that share phones and pass money around among themselves.
2. **Money mules**: many scam victims pay one mule, who quickly forwards the money to a collector or cashes it out at an agent.
3. **Laundering loops**: money goes A → B → C → A in almost identical amounts, to make it look legitimate.
4. **Account takeover**: an old, quiet account suddenly sends night-time transfers to brand-new "drop" accounts, which then cash out.

**Want a bigger network?** Run `python generate_payments_graph.py --accounts 1000000` in this folder. It overwrites the two data files, takes a few minutes, and makes the notebook much slower. Other options: `--tx-per-account`, `--seed` and `--out`.

## Results (test set: 40,000 accounts, 611 of them fraud)

| Model | Looks at | PR-AUC | Precision | Recall | Fraudsters caught when reviewing the riskiest 400 accounts |
|---|---|---|---|---|---|
| Logistic regression | each account on its own | 0.439 | 0.419 | 0.535 | 197 |
| XGBoost | each account on its own | 0.731 | 0.699 | 0.651 | 323 |
| **Graph transformer** | each account **and its contacts** | **0.918** | **0.862** | **0.858** | **380** |

**How to read this:** fraud is only 1.5% of accounts, so plain accuracy is useless (a model that calls nobody a fraudster is 98.5% "accurate"). **PR-AUC** measures how well a model ranks the real fraudsters at the top of its list (1.0 = perfect; random guessing scores about 0.015). Reviewing the 400 accounts the graph transformer finds most suspicious catches 380 fraudsters and bothers only 20 honest customers.

## How to run it

```bash
pip install numpy pandas matplotlib scikit-learn xgboost networkx
pip install torch --index-url https://download.pytorch.org/whl/cpu
```

Then open `graph_transformer.ipynb` and run all cells. It takes about 7 minutes on a normal laptop CPU (no GPU needed). The graph transformer is written in plain PyTorch, so no special graph library is required.
